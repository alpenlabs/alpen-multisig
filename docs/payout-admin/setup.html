1. The test round

One host runs the shared regtest chain and the coordinator release binary. Every tester runs their own Bitcoin Core in regtest with txindex=1, peered with the host's node, plus the desktop release binary, and connects their own Ledger. The testers' Ledger keys are the Payout Administrator multisig. The host can also be a tester.

Each desktop talks only to the Bitcoin Core on its own machine, as the PRD intends: every admin checks false claim reports against their own node. Bitcoin RPC never leaves a machine. Only the peer-to-peer port of the host's node and the coordinator port are shared.

Everyone uses the same chain, seeded params.toml, and ordered roster.toml. The seeder creates contested unpaid claims and funds every Admin Wallet. A majority is the default signing threshold. For example, three testers need two signatures. This round covers Payout Administrators only. It needs no ASM, Strata RPC service, Electrum server, or Docker.

Use only an isolated trusted LAN or VPN. The coordinator uses plain HTTP in this kit. Open host ports 18444 (regtest peer-to-peer) and 3000 (coordinator) to testers only. Do not expose them to the Internet. Keep RPC port 18443 on loopback on every machine. All coins in this round are regtest coins.

2. Prerequisites on every build machine

Check out the same revision as the other testers. Run the commands below from the repository root unless a command changes directory. You need Git, a C/C++ toolchain, rustup, Node, and network access for Cargo git dependencies and npm packages.

macOS

Install Xcode Command Line Tools, or install and open full Xcode once:

xcode-select --install

Linux

For Debian/Ubuntu, install the Tauri 2 libraries plus the repository's Linux build dependencies. USB development libraries support the hardware transports.

sudo apt update
sudo apt install build-essential curl wget file pkg-config \
  libwebkit2gtk-4.1-dev libgtk-3-dev libsoup-3.0-dev \
  libjavascriptcoregtk-4.1-dev libxdo-dev libssl-dev \
  libayatana-appindicator3-dev librsvg2-dev libudev-dev libusb-1.0-0-dev

Other distributions need equivalent packages. See the official Tauri 2 prerequisites. Linux package details are also in the repository's docs/operations/desktop-build-linux.md.

Rust and Node on both platforms

Install Rust through rustup. The repository pins nightly-2026-07-01 in rust-toolchain.toml. Do not substitute stable.

rustup toolchain install nightly-2026-07-01 --component cargo,clippy,rustc,rustfmt
rustup show active-toolchain
rustc --version

Use Node 22.23.4. With fnm in zsh:

eval "$(fnm env --shell zsh)"
fnm install 22.23.4
fnm use 22.23.4
node --version
npm ci

For bash use fnm env --shell bash. Alternatively, after loading nvm, run nvm install 22.23.4, nvm use 22.23.4, then npm ci. Run npm ci at the repository root: this is an npm workspace with desktop-app as a member.

Bitcoin and Ledger

The host and every tester need bitcoind and bitcoin-cli from Bitcoin Core 28 or newer. Version 28 adds the TRUC relay rules used by payouts. Download it from bitcoincore.org or use your package manager, for example brew install bitcoin on macOS.

Each tester needs a Ledger, a USB data cable, and Bitcoin Test 2.4.6 or newer installed on it. Unlock the device and open Bitcoin Test when instructed. Close other apps that hold the USB connection. Linux users need Ledger USB/udev permissions for their normal user. Trezor and BitBox are not supported. Never share recovery words or private keys.

3. Build the release binaries

# Repository root. The host builds the coordinator; every tester builds the desktop app.
cargo build --release -p orchestrator-be
# macOS: only the .app (the DMG step needs Finder scripting and is not needed here)
(cd desktop-app && npm run tauri build -- --bundles app)
# Linux: an AppImage, or deb
(cd desktop-app && npm run tauri build -- --bundles appimage)

The coordinator package declares its binary name as server in orchestrator-be/Cargo.toml. The desktop command runs the TypeScript/Vite build, compiles Rust, then bundles the app. The first build takes a while. Build natively on each tester's platform. The coordinator address is set later in the app, not at build time.

An unsigned macOS build may be blocked on first open. In Finder, right-click Strata Multisig.app, choose Open, then confirm Open if offered. If macOS requires it, use Privacy & Security's Open Anyway for this locally built app. Quit it after this first opening. Use the launcher below for the test round so the network environment is explicit.

4. Host: prepare an isolated round directory

Use a new directory for each round. These commands use a sibling of the repository, so generated keys and chain data are not committed. Keep this shell open for the later host commands.

# Repository root
REPO_ROOT="$PWD"
ROUND="$REPO_ROOT/../payout-round-01"
mkdir -p "$ROUND"
cp docs/payout-admin/kit/* "$ROUND/"
mkdir -p "$ROUND/bitcoin"
chmod 700 "$ROUND"
chmod 600 "$ROUND/coordinator.env" "$ROUND/bitcoin.conf"

$ROUND/bitcoin.conf is the host's node. It keeps RPC on loopback for the seeder and the coordinator and listens for testers' nodes on the regtest peer-to-peer port 18444. Keep txindex=1, server=1, and the regtest settings. Its RPC user and password are user and password, the values the app's Local mode uses; they are acceptable only because RPC stays on loopback and the chain is regtest.

bitcoind -datadir="$ROUND/bitcoin" -conf="$ROUND/bitcoin.conf" -daemon
bitcoin-cli -regtest -datadir="$ROUND/bitcoin" -conf="$ROUND/bitcoin.conf" getblockchaininfo
bitcoin-cli -regtest -datadir="$ROUND/bitcoin" -conf="$ROUND/bitcoin.conf" getindexinfo

Wait for RPC to respond. Check that chain is regtest and txindex.synced is true. Do not seed until both are correct. The config's fallbackfee is for Core wallet funding on a chain without fee estimates; it does not choose the app's payout fee.

5. Each tester: read their Ledger identity

Close the desktop app and other Ledger clients. Unlock your Ledger and open Bitcoin Test. From your repository root:

LEDGER_NETWORK=regtest LEDGER_PHYSICAL=1 \
  cargo test -p alpen-multisig-e2e-tests --test ledger_identity -- --nocapture

This helper reads the app name/version, master fingerprint, and account xpub. It does not sign. Find the LEDGER_IDENTITY JSON line. Check app is Bitcoin Test, version is at least 2.4.6, and accountPath is m/86'/1'/73'. Send only fingerprint and accountXpub, plus your label, to the host.

The host copies the template and replaces every placeholder:

cp "$ROUND/roster.example.toml" "$ROUND/roster-input.toml"

Keep network = "regtest". Add one [[admins]] per tester. Copy accountXpub into xpub and the exact eight hexadecimal fingerprint characters into fingerprint. Agree on the order before seeding. The derived xpub/0/0 at each position becomes that tester's admin key in params.toml. Do not reorder the roster later.

6. Host: seed the chain

The seeding test connects to the running Core node. It starts neither Core nor the coordinator. Run from the repository root with the completed roster:

PAYOUT_SEED_DIR="$ROUND/seed" \
PAYOUT_SEED_RPC_URL=http://127.0.0.1:18443 \
PAYOUT_SEED_RPC_USER=user \
PAYOUT_SEED_RPC_PASS=password \
PAYOUT_SEED_ROSTER="$ROUND/roster-input.toml" \
PAYOUT_SEED_CLAIMS=5 \
PAYOUT_SEED_FUND_SATS=100000000 \
  cargo test -p alpen-multisig-e2e-tests --test payout_regtest_seed -- --nocapture

PAYOUT_SEED_THRESHOLD is optional; omitted, it is n/2 + 1. For three testers, set it to 2 explicitly if desired. Claims default to 5. Funding defaults to 100,000,000 sats per admin, split into three coins and mined to at least six confirmations. Without PAYOUT_SEED_DIR the test returns without seeding.

Output in seed/Use
params.tomlDeployment root of trust. Same file for coordinator and all desktops.
roster.tomlValidated roster, in params order. Same file for all desktops.
reports.jsonFalse claim reports to paste into Block Payouts. The ACK has at least six confirmations.
seed.jsonSummary with transaction ids, heights, funded addresses, and coordinator environment values.
seed-keys.jsonGenerated bridge/covenant test keys for reruns. Keep on the host, outside Git. Do not distribute.

Distribute only params.toml, roster.toml, and reports.json to each tester over your trusted channel. Each tester saves them locally and checks they received the same files. Do not point Settings at the unfilled example roster.

7. Host: start the coordinator binary

The copied coordinator.env includes every setting read by Config::from_env, plus logging. Its relative params path resolves from the environment file's directory. Check it points at the seeded file. Leave DATABASE_URL unset for in-memory storage.

REPO_ROOT="$REPO_ROOT" "$ROUND/run-coordinator.sh" --dry-run
REPO_ROOT="$REPO_ROOT" "$ROUND/run-coordinator.sh"

Keep the process running in that terminal. From another terminal:

curl --fail http://127.0.0.1:3000/api/v1/health
curl --fail http://127.0.0.1:3000/api/v1/ready

The first checks the process; the second checks Bitcoin RPC reachability. Neither proves a tester's roster matches. The host shares its LAN address and ports with testers. The kit sets STRATA_ADMIN_STATE_RPC_URL=http://127.0.0.1:8080 explicitly. Payouts do not use this service. The code defaults to that URL if absent, although the operations runbook lists it as required. Do not use mock:// in a normal release build.

In-memory storage loses pending/past records and login sessions on coordinator restart. Restarting does not undo transactions on the chain. Use a fresh coordinated round for a clean reset.

8. Each tester: start your node, launch and configure the desktop

Your own regtest node

Copy tester-bitcoin.conf into a new data directory, put the host's LAN address into its connect= line, and start the node. It downloads the shared chain from the host.

NODE="$HOME/payout-round-01-node"
mkdir -p "$NODE"
cp docs/payout-admin/kit/tester-bitcoin.conf "$NODE/bitcoin.conf"
# Edit "$NODE/bitcoin.conf": replace HOST in connect=HOST:18444
bitcoind -datadir="$NODE" -conf="$NODE/bitcoin.conf" -daemon
bitcoin-cli -regtest -datadir="$NODE" -conf="$NODE/bitcoin.conf" getblockchaininfo
bitcoin-cli -regtest -datadir="$NODE" -conf="$NODE/bitcoin.conf" getindexinfo

Wait until blocks equals the host's height and txindex.synced is true. If you are the host and also a tester, skip this: the host node already uses the RPC port and credentials Local mode expects.

Launch the desktop

Quit any existing instance. From the repository root:

docs/payout-admin/kit/run-desktop.sh --dry-run
docs/payout-admin/kit/run-desktop.sh

On macOS the launcher runs the executable inside the built .app. On Linux it selects the single built AppImage, or the release executable if no AppImage exists. To use an installed .deb binary, set DESKTOP_BIN=/usr/bin/desktop-app. For a custom target directory, set RELEASE_DIR to its release directory. For an installed macOS app:

DESKTOP_BIN="/Applications/Strata Multisig.app/Contents/MacOS/desktop-app" \
  docs/payout-admin/kit/run-desktop.sh

The script exports BITCOIN_NETWORK=regtest and ALLOW_INSECURE_HTTP_URL=1 only for its process and the launched app. It writes no file or shell profile. Run the script; do not source it.

Settings > Node

Select Local node. In this mode the app uses the Bitcoin Core at http://127.0.0.1:18443 with user user and password password, which is what tester-bitcoin.conf sets. Replace HOST below with the host's LAN address.

SettingValue for this round
ConnectionLocal node
Orchestrator URLhttp://HOST:3000/api/v1
Bridge parameters file (params.toml)Absolute local path to the seeded params.toml you received
Signer roster (admin xpubs)Absolute local path to the seeded roster.toml you received

Save the settings. They persist in node-config.json in the app configuration directory. The network is a process setting, not a Node setting. The Strata and Electrum status shown in the app may read unreachable: Payout Administrator flows need neither.

Why Local and not Custom: on this branch the Orchestrator URL field exists only in Local mode. Plain http:// to another machine is refused by the app unless ALLOW_INSECURE_HTTP_URL=1 is set; the launcher sets it for the launched app only, for this regtest round.

Sign in as Payout Administrator

Connect and unlock your Ledger, then open Bitcoin Test. Choose the Ledger connection and the Payout Administrator role. Review the app's sign-in checklist. Compare every message screen with the Ledger, then approve only if it matches. The connected fingerprint and account xpub must match your roster entry. The app also checks the coordinator's deployment against your params file.

Open Block Payouts and its Admin Wallet dialog. Continue with the feature guide and physical Ledger tests.

9. Funding and confirmations

No tester needs to send funds manually: the seeder funds every Admin Wallet's first receive address, m/86'/1'/73'/0/0. Compare the funded address in seed.json with the intended tester. The dialog shows confirmed incoming funds; incoming unconfirmed coins are not displayed. Fee inputs must be confirmed.

Regtest has no automatic miner. After a payout broadcasts, the host mines a block to confirm it. Create a separate mining wallet once, then obtain an address and mine:

bitcoin-cli -regtest -datadir="$ROUND/bitcoin" -conf="$ROUND/bitcoin.conf" createwallet round-miner
MINING_ADDRESS="$(bitcoin-cli -regtest -datadir="$ROUND/bitcoin" -conf="$ROUND/bitcoin.conf" \
  -rpcwallet=round-miner getnewaddress)"
bitcoin-cli -regtest -datadir="$ROUND/bitcoin" -conf="$ROUND/bitcoin.conf" \
  generatetoaddress 1 "$MINING_ADDRESS"

Use generatetoaddress 6 "$MINING_ADDRESS" for six new blocks. On a later host session, load the existing wallet with loadwallet round-miner if needed, instead of creating it again. Give the app time to refresh; payout lists poll every 15 seconds. Do not mine while a test specifically needs an unconfirmed transaction.

10. Reset together

  1. Ask every tester to close the app. Stop the coordinator with Ctrl-C.
  2. Stop this round's node with the command below. Wait until it exits.
  3. Keep the old round directory as an archive. Repeat host setup using a new sibling directory such as payout-round-02, with a fresh Bitcoin data directory and fresh seed output. Never run both nodes on the same ports.
  4. Reuse the agreed public roster if the testers and devices are unchanged. Seed again, distribute the new files, update every desktop's local paths, and restart the coordinator and desktops.
bitcoin-cli -regtest -datadir="$ROUND/bitcoin" -conf="$ROUND/bitcoin.conf" stop

Restarting only the coordinator clears its memory but leaves spent connectors and balances on chain. Changing only a roster breaks its correspondence with params. Do not combine old reports with a fresh chain. For additional claims on the same deployment, the seeder contract preserves bridge/covenant keys in seed-keys.json; retain that file for reruns.

Desktop settings and wallet history survive app restarts. For a fully pristine UI test, use a fresh OS test account and configure it with the new round files. Do not reset or erase the Ledger.

11. Troubleshooting

Node is not regtest

Check getblockchaininfo on the exact host/port configured in Settings. It must report regtest. Check the coordinator env and relaunch the desktop with the kit. A URL does not select the app's network. Use the dedicated round data directory.

No txindex, or transactions cannot be found

Check getindexinfo for txindex with synced: true. Stop Core, enable txindex=1, restart and let it finish indexing. Keep pruning disabled. Check that reports belong to this chain. Both coordinator and desktop need access to indexed transactions.

Roster mismatch or Ledger not recognized

Use the seeded roster, not the template. Check network, order, fingerprints and complete account xpubs. Every roster xpub/0/0 must match the key at the same position in params. Read the identity again with the correct device and regtest account. All desktops and the coordinator must use the same params file.

Ledger app not open, USB busy, or wrong app version

Unlock the Ledger, open Bitcoin Test, and close other USB clients. Check Linux device permissions if access is denied. Bitcoin Test must be 2.4.6 or newer. Update through the device's supported app installation flow if needed. If you change the app version after sign-in, sign in again so the checklist matches the device.

Coordinator says “not configured”

Set PAYOUT_ADMIN_PARAMS_PATH to the seeded params file and restart with run-coordinator.sh. Confirm the printed path exists relative to the env file directory. Check BITCOIN_NETWORK=regtest. The launcher refuses missing params; launching the binary directly without the setting leaves payout routes disabled.

BITCOIN_NETWORK is missing but the app still says regtest

The code defaults to regtest only when the variable is absent. Startup also loads desktop-app/.env at the build machine's compiled-in path, then discovers a .env from the working directory or its ancestors. Existing environment variables win. The launcher explicitly exports regtest so an inherited or discovered setting cannot silently select another network. It never writes an .env or edits your shell profile.

Connection refused, unauthorized, or wrong host

Check your own node first: bitcoin-cli -regtest -datadir="$NODE" -conf="$NODE/bitcoin.conf" getblockchaininfo. Its height must equal the host's; if it does not, check getpeerinfo, the host address in connect= and the host firewall for port 18444. Check the Orchestrator URL, including /api/v1, with curl http://HOST:3000/api/v1/health. An error that says the orchestrator base_url must use https means the app was not started through the launcher. Do not use the Strata RPC field for the coordinator.

Launcher cannot find a binary or refuses .env

Check the build completed and use an absolute COORDINATOR_BIN or DESKTOP_BIN override for a custom build path. A copied kit needs REPO_ROOT. The coordinator launcher refuses .env files in its working directory or ancestors to prevent accidental storage settings; place the round outside that tree. Run both scripts with --dry-run to inspect paths without starting processes.
